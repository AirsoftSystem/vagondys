## 4. PROMPT DE DÉVELOPPEMENT ULTIME

### Contexte Général

Je développe **VAGONDYS**, un système complet de gestion de parties d'airsoft avec des cibles connectées ESP32. L'infrastructure est multi-villes (Nantes, Lyon, Madrid, etc.) avec des bases Supabase MASTER, PUBLIC et STAFF pour chaque ville.

Actuellement, une **application Flutter** (`scores_screen.dart`) contrôle chaque couloir individuellement. Je souhaite **migrer cette logique vers une application web Next.js** intégrée au portail STAFF, avec **quatre niveaux de jeu** :

| Niveau | Description | Spécificité |
|--------|-------------|-------------|
| **Mode Normal** | Contrôle mono-couloir (1 ESP32) | 1-4 joueurs, jeu tour par tour |
| **Mode Tournoi** | Lancement synchronisé de plusieurs couloirs | 1 vs 1 par couloir, départ simultané |
| **Mode Compétition** | Gestion de tournois avec classements | Élimination directe, arbre de tournoi |
| **Mode Notoriété** | Sessions spéciales avec influenceurs | 1 champion vs 3 challengers, calcul de réputation (PCH) |

### Points Clés

1. **Les boutons `START_GAME`, `NEXT_PLAYER`, `NEXT_TURN` sont déclenchés UNIQUEMENT par le STAFF**
2. **Les modes "Officiels"** (Tournois, Compétitions, Notoriété) nécessitent une synchronisation parfaite
3. **Le décompte vocal (3-2-1-VIZ) est joué sur l'interface STAFF**, pas sur les ESP32
4. **L'envoi des commandes aux ESP32 est PARALLÈLE** (`Promise.all`) pour une synchronisation exacte
5. **Règle de victoire officielle** : 3 manches gagnées = 120 tirs (20 tirs × 2 séries × 3 manches)
6. **Les scores et statistiques sont sauvegardés** dans les bases STAFF de chaque ville
